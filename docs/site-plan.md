# Multi-page site plan (compiled from competitor audits)

Sources: `audit-aspen.md` (108 URLs, 31 treatments) and `audit-clove.md` (~1,370 URLs, 15 treatments). We copy structure and style only. All wording is written fresh and all images are our own.

## 1. What makes them feel "big"

| Signal | Aspen | Clove | Cost for us |
|---|---|---|---|
| Breadth of treatment pages | 31, one template | 15, one template | Cheap (template + data) |
| Mega-menu on every page | Yes, grouped | Yes, 16 items | Cheap |
| Rating badge up top | 4.9 stars, 456 reviews | 4.9 stars, lakhs of reviews | Cheap (we have real Google reviews) |
| Long page (1,400-3,300 words), FAQs, cost section | Yes | Yes | Medium (writing) |
| Doctor profiles / named experts | 4 profile pages | Generic team only | Cheap (one doctor) |
| Local / area pages | ~10 neighbourhood pages | 690 clinic pages | Cheap for 6-8 areas |
| Blog | 35 posts | 562 posts | Medium, do a few |
| Always-on CTA (call, WhatsApp, book) | Yes | Yes | Done |
| Press, awards, influencers, branches | Yes | Yes | Skip |

## 4. Treatment page template (our version of the common pattern)

Order, taken from the shared structure of both sites:
1. Breadcrumb + H1 (`<Treatment> in Palam Vihar, Gurugram`), short intro, call/WhatsApp buttons, rating badge
2. What is it
3. Who needs it / symptoms
4. Types (where relevant)
5. Procedure, 5-6 numbered steps
6. Benefits (cards)
7. Aftercare
8. Cost: honest "from" range and what affects the price (confirm prices with Dr. Jain)
9. Why Dr. Jain (doctor box with credentials)
10. FAQs (6-8), with `FAQPage` schema
11. Real Google reviews for this treatment, if any
12. Related treatments (Clove lacks this; Aspen's linking is via blog, so we add it)
13. Closing CTA + appointment form (WhatsApp)

Target 900-1,400 words per page, which is enough depth without bloat.

## 5. SEO patterns to reuse

- Title: `<Treatment> in Palam Vihar, Gurugram | From ₹X | Dr. Disha Jain Dental Clinic` (add price only once confirmed)
- Schema: `Dentist` (site-wide), `MedicalProcedure` + `FAQPage` + `BreadcrumbList` per treatment page, `AggregateRating` only if it matches verifiable reviews
- Internal links: mega-menu on every page, related treatments, blog to treatment and back
- One sitemap.xml and robots.txt, canonical tags
- Avoid their mistakes: duplicate pages, a typo slug, missing meta descriptions

## 6. Technical approach (light and cheap)

- Plain HTML generated by a small Node build script from `data/treatments.json` plus 3 templates. No framework, no runtime JS needed for content.
- Shared header, mega-menu and footer partials. Existing CSS reused and extended.
- Images: our own photos plus a few simple illustrations. WebP, under 120 KB each. Lazy-loaded.
- Hosted on GitHub Pages (as now). Output into the repo root or `/docs` build folder.
- Target under 150 KB per page excluding images.
